## Usage

```bash
s3ctl [flags]
s3ctl --help        # the commands you'll use most
s3ctl --help-full   # every flag, template and CSV column
```

Flags win over the JSON config, and the config wins over built-in defaults. Most flags have a config
key of the same name in snake case, so `--enable-versioning` becomes `enable_versioning`; the tables
note the exceptions. Without `--config`, s3ctl reads `$XDG_CONFIG_HOME/s3ctl/config.json`, then
`$HOME/.config/s3ctl/config.json`.

## Input

Which provider to use, which buckets to work on, and where the rest of the settings come from.
[Batch provisioning](/s3ctl/guides/batch-provisioning/) lists the CSV columns.

## S3 connection

Used by the `s3` provider. When neither a profile nor explicit keys are set, the AWS SDK's standard
credential discovery applies. Use a profile or explicit keys, not both.

# s3ctl website

This folder is the source of the s3ctl documentation site,
<https://netspeedy.github.io/s3ctl/>, built with Astro and Starlight. The pages are
Markdown and MDX in `src/content/docs`, and many of them use components that only
render on the site, so read the docs there rather than here. The files in the
repository's [`docs/`](../docs/) folder are pointers to the site, apart from
[`release.md`](../docs/release.md).

The sidebar groups, their colours and icons, and which header tab shows which group
are defined in `src/lib/sections.ts` and matched to the sidebar in
`astro.config.mjs` by label.

The components and styles are the same in every netspeedy docs site and use the
`ns-` prefix. What's particular to s3ctl, such as its name, description, links and
footer columns, is in `src/lib/site.ts`.

## Working on it

Run these from the repository root:

```bash
make website-install   # npm ci, from package-lock.json
make website-dev       # local server with live reload
make website-build     # production build into website/dist/
make website-check     # every page, the search index, icons, share card and internal links
make website-test      # the theme, header, version menu and an archived line in headless Chrome
make website-capture   # desktop and phone screenshots in both themes into website/.captures/
```

`make website-check` reads `website/dist`, so it always runs after the build. CI
builds with the newest Node 22 release (`check-latest` in setup-node), since the
version a runner has cached can be older than Astro's minimum, which is in
`engines` in `package.json`.

`public/og-image.png`, `public/og-image.svg`, the favicons, the Apple touch icon and
`src/assets/mark.svg` are generated by `make readme-hero` along with the README
banner, so edit `scripts/readme/build_readme_hero.py` rather than the files.

## Versioned docs

Only the latest release line's pages live here. When a new minor ships, the Release
Assets workflow rebuilds the outgoing line from git with `SITE_ARCHIVE=vX.Y`, and
the Pages workflow publishes it under `/s3ctl/vX.Y/` beside the latest. Never copy
pages into per-version folders, and keep page links root-relative (`/s3ctl/...`) so
archived builds can rewrite them. The "Versioned docs" section of
[docs/release.md](../docs/release.md#versioned-docs) has the details, including how
to rebuild an archive by hand.

## How it's published

Deploy Pages Site runs on every push to `main`, when a release is published and
after each Release Assets run. It builds the latest line, unpacks the archived
lines into it, runs `make website-check` over the result and deploys it. Dependabot
checks the npm dependencies here daily and titles its pull requests `chore:`, so a
site update doesn't cut a CLI release.
